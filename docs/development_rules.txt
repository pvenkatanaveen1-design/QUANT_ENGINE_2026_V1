QUANT_ENGINE_2026 - Development Rules (Strict)

1) Python File Standards
- Every Python file must include comments that explain important lines and decisions.
- Every Python file must be beginner friendly (clear naming, simple flow, readable structure).

2) Python-to-Text Pairing (Mandatory)
- Every Python file must have one matching .txt explanation file.
- Naming rule example: bus.py -> bus.txt
- The .txt file should explain purpose, flow, inputs/outputs, and run/test steps.

3) System Visibility and Status
- Every system must publish status to Redis.
- Every system must be visible in the UI dashboard.
- If a system is not visible in UI and not reporting to Redis, it is incomplete.

4) Required Development Flow (Do in Order)
- Step 1: Create one system.
- Step 2: Test that system.
- Step 3: Show that system in UI.
- Step 4: Move to the next system only after Step 3 is done.

5) Single-System Focus Rule
- Never build multiple systems at once.
- Only one active system is allowed during development and validation.

6) Cursor AI Update Condition (Mandatory)
- Every time any script, command flow, or run process is changed, Cursor AI must update related guide files in `cmd_script/`.
- At minimum, review and update:
  - `cmd_script/run_types_and_conditions.txt`
  - `cmd_script/script_run_process_steps.txt`
  - `cmd_script/question_to_command_map.txt`
- If code is changed but command docs are not updated, the task is incomplete.
